# Application integration notes

Use the original Electrobun APIs in an optional native module and Furin's controller for coordinated application operations. See [the public API](./README.md) and [host ownership](./native-host.md).

The Elysia root declares main with `desktopApp({ window: { title, frame, ...sdkOptions } })`. Independent API plugins install `desktopContext`; native modules call `getDesktopHost()`. Both receive the same live controller. SDK menus, tray, dialogs, notifications, shortcuts, screens, sessions, views, RPC and GPU capabilities remain available through `electrobun/main` and its original public subpaths.

Application data/profile initialization and disposal belong to Elysia `.onStart()` and `.onStop()`. Keep dependent startup steps in one async hook. Native events must handle their own errors. Handle magnet links, `.torrent` files and the OAuth callback scheme in `desktopApp(({ ...services }) => ({ onOpen(event) { ... } }))` on the Elysia root. Remove the `globalThis` handoff (`nativeControl.tofuNativeOpen`) and the native entrypoint's `open-url` subscription: in `furin dev` the backend runs in another process, so a handler stored on `globalThis` never reaches the native entrypoint. `onOpen` receives `{ type: "url", url }` or `{ type: "file", path }` once per event, after startup, in builds and in development. Background policy, association helpers and coordinated quit/restart/update installation remain Furin responsibilities.

For existing data directories, declare a runtime `dataDir` policy; resolve user environment at launch, not during packaging. Existing profile markers, business input handling and data migrations remain application-owned. No application source in the reference Tofu checkout is modified by this integration.

For React UI actions, use `useDesktop` from `@teyik0/furin-electrobun/client`, rather than checking the backend runtime or calling a native action over HTTP. In particular, replace `POST /api/updates/open-download` with `desktop.browser.open(downloadUrl)` when `desktop.status === "desktop"`; retain a normal anchor in Web/SSR. Delete that POST endpoint in the consuming application and retain `GET /api/updates/download` only for file delivery. See the [complete React example and authentication limits](./README.md#react-host-capabilities): opening a URL does not transfer the webview session to the system browser, and a private loopback download URL may require a different application-owned delivery/authentication flow.
