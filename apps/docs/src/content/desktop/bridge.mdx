# React and the typed desktop bridge

`useDesktop()` detects the interface currently displaying your page and exposes the built-in system-browser action. It is safe to import during SSR and does not require a provider, server action or application endpoint.

## Detect the current interface

```tsx
import { useDesktop } from "@teyik0/furin-electrobun/client";

export function InterfaceStatus() {
  const desktop = useDesktop();
  return <span>{desktop.status}</span>;
}
```

| Status | Meaning |
|---|---|
| `initializing` | SSR/hydration snapshot, before the handshake completes |
| `web` | The current page has no Electrobun event bridge |
| `desktop` | Its managed native window acknowledged the handshake |
| `unavailable` | A bridge exists but did not acknowledge in time, or stopped responding |

This describes the current interface, not the backend. A remote browser connected to a desktop backend remains `web`.

## Open the system browser

```tsx
import { useState } from "react";
import { useDesktop } from "@teyik0/furin-electrobun/client";

export function ExternalLink({ url }: { url: string }) {
  const desktop = useDesktop();
  const [failed, setFailed] = useState(false);

  return (
    <>
      <a href={url} onClick={(event) => {
        if (desktop.status !== "desktop") return;
        event.preventDefault();
        setFailed(false);
        void desktop.browser.open(url).then((result) => {
          setFailed(!result.ok);
        });
      }}>
        Open link
      </a>
      {failed ? <p role="alert">Could not open the system browser.</p> : null}
    </>
  );
}
```

Web and SSR keep a normal anchor. On desktop, `browser.open(url)` resolves to `{ ok: true }` or `{ ok: false, reason }`, where `reason` is `unavailable`, `invalid-url` or `open-failed`.

The native acknowledgement confirms that the operating system accepted the opening request, not that the destination loaded. Requests time out after five seconds; a timeout cannot prove an already dispatched action did not run. Unmounting cancels pending waits and releases listeners.

## URL and session boundaries

HTTP, HTTPS and `mailto:` are allowed. Embedded credentials, malformed URLs, custom schemes, `javascript:`, `data:` and `file:` are refused. Relative URLs resolve against the current page URL at call time. The host validates the resulting URL again and rejects its private session-bootstrap origin.

Opening a URL does not forward cookies, tokens or the WebView's authentication. Protected downloads need a browser-accessible session or an appropriately scoped download URL. Do not expose the desktop bootstrap cookie to make a download work.

## Custom RPC

The built-in bridge uses Electrobun's event transport and preserves application RPC transports. It only exposes `browser.open`; it is not a generic native-method invoker. For application-specific RPC, use the original SDK RPC types and pass your RPC object to a managed window. See [Windows & Lifecycle](/docs/desktop/windows) and [Electrobun BrowserWindow](https://docs.electrobun.dev/electrobun/apis/browser-window/).
