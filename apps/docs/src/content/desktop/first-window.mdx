# Your first desktop window

Declare the primary window on your Elysia root with `desktopApp()`. Install it before listening and before mounting the rest of the application.

## Register the primary window

```ts
// src/server.ts
import { furin } from "@teyik0/furin";
import { desktopApp } from "@teyik0/furin-electrobun/server";
import { Elysia } from "elysia";

const app = new Elysia()
  .use(desktopApp({
    window: {
      title: "Relay",
      frame: { width: 1100, height: 780 },
      titleBarStyle: "hiddenInset",
      renderer: "native",
    },
  }))
  .use(await furin({ style: "tanstack" }))
  .listen({ hostname: "127.0.0.1", port: 4242 });

export default app;
```

Keep your existing pages and root layout. The window loads the Furin app; it does not need a separate HTML file or React root. Window options come from Electrobun, while Furin owns the managed URL and navigation boundary.

## Run in development

With the [preload configured](/docs/desktop/installation#initialize):

```sh
bun --hot src/server.ts
```

The preload only activates when `--hot` runs the configured server entry (`serverEntry`, `src/server.ts` by default), and hands off to `furin dev`. It opens the native window and an authenticated system-browser session against the same backend. Choose one interface with a flag:

```sh
bunx --bun furin dev --desktop  # native window only
bunx --bun furin dev --web      # Web app only, without the native SDK
```

Development runs two processes: Furin's `bun --hot` worker serves the backend (Elysia, API, SSR, sync), and a native shell owns the Electrobun windows, menus, tray and your native entrypoint. They talk over an authenticated loopback channel.

| You edit | What happens |
|---|---|
| A page or component | Bun HMR and React Fast Refresh; the window stays open |
| A route, API, database or sync module | The backend reloads in place; windows stay open and `globalThis` state survives |
| The native entrypoint or its imports | Only the native shell is rebuilt and relaunched; the backend keeps running |

Quitting the desktop app ends the development session, and Ctrl-C stops the backend, then the shell. Keep the listener port fixed: a port that changes on reload (`port: 0`) relaunches the shell.

## Startup ownership

The generated host waits for Elysia startup hooks before opening the primary window. Put shared startup work in `.onStart()` and cleanup in `.onStop()`.

Do not create another primary window in a native entrypoint; there is no separate launch function to call. Use [Windows and lifecycle](/docs/desktop/windows) for additional windows and native controls.
