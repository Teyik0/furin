# CLI Reference

Furin ships with a CLI for the Bun-powered development server, production builds, and static previews.

---

## `furin dev`

Run the application's server entry with Bun hot reload:

```bash
bunx furin dev [options]
```

The command uses `serverEntry` from `furin.config.ts`, or `src/server.ts` when it is not configured. It sets `PORT`, starts the entry with `bun --hot`, and prints both local URLs:

```text
◆ Development server starting
  Local:     http://localhost:3000/
  DevTools:  http://localhost:3000/_furin/devtools
```

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--config` | `string` | `furin.config.ts` | Config file path |
| `--port` | `number` | `PORT` or `3000` | Listening port exposed through `process.env.PORT` |
| `--open-devtools` | `boolean` | `false` | Open the Furin DevTools dashboard once the server responds |

No browser is opened unless `--open-devtools` is explicitly provided.

```sh
furin help
furin dev
furin build
furin preview
```

The generated project already exposes these through `bun run build`, `bun run start`, and `bun run dev`.

## `furin build`

```sh
furin build [options]
```

| Flag | Value | Default | Meaning |
|---|---|---|---|
| `--target` | `bun`, `static`, `package`, `node`, `vercel`, `cloudflare`, or `all` | `bun` | Select output |
| `--pagesDir` | Path | Config or auto-detected | Build one explicit app |
| `--prefix` | URL prefix | `""` | Prefix paired with the explicit pages directory |
| `--config` | Path | Auto-discovered | Use another config file |
| `--compile` | `server` or `embed` | No executable; inherits `bun.compile` when configured | Produce a Bun executable |
| `--analyze` | Boolean flag | `false` | Write client Bun metafiles under `.furin/build/analysis` |

`--compile` without a value means `server`; `--compile=embed` is also accepted.

```sh
# Bundled Bun server
furin build --target bun

# Executable plus assets on disk
furin build --target bun --compile server

# One self-contained executable
furin build --target bun --compile embed

# Pure static output
furin build --target static

# Publishable Furin/Elysia plugin
furin build --target package --pagesDir ./src/admin --prefix /admin

# Bun and static outputs
furin build --target all
```

`all` currently means the implemented deploy targets `bun` and `static`; it deliberately excludes `package`, which is an alternative packaging of one app.

### Target Status

| Target | Status | Main output |
|---|---|---|
| `bun` | Implemented | `.furin/build/bun` |
| `static` | Implemented | `static.outDir`, default `dist` |
| `package` | Implemented | `.furin/build/package` |
| `node` | Planned; command fails | None |
| `vercel` | Planned; command fails | None |
| `cloudflare` | Planned; command fails | None |

Every successful build writes `.furin/build/manifest.json`. It records route modes, app prefixes, output paths, build IDs, and target-specific metadata.

### Analyze Output

`--analyze` writes Bun metafiles for client builds. They describe emitted byte sizes and import contributions, but do not measure startup latency, request throughput, memory, or edit-to-paint time.

## `furin preview`

Serve a completed static export locally:

```sh
furin preview [options]
```

| Flag | Default | Meaning |
|---|---|---|
| `--dir` | `static.outDir` or `dist` | Directory to serve |
| `--basePath` | `static.basePath` or `""` | Hosting prefix to simulate |
| `--port` | `3000` | Local TCP port |
| `--config` | Auto-discovered | Alternate config file |

```sh
furin build --target static
furin preview --port 4173
```

Preview handles clean HTML routes and the generated `404.html` fallback. It is a validation server, not a production application runtime.

## Development

`furin dev` remains a small supervisor around Bun rather than replacing the application's Elysia entrypoint. This preserves custom plugins, middleware, and `.listen()` configuration while giving you:

- React Fast Refresh
- Server-side hot reload
- File-system-based routing updates
- the dedicated Furin DevTools dashboard

The direct Bun command remains supported:

```sh
bun --hot src/server.ts
```

Route discovery, generated types, React Fast Refresh, server re-imports, diagnostics, and DevTools are activated by `furin()` in development. See [Dev Mode HMR](/docs/dev-hmr) for the full internals.
