# CLI Reference

The Furin CLI builds production artifacts and previews static exports. Development runs the application entry directly with Bun.

```sh
furin help
furin build
furin preview
```

The generated project already exposes these through `bun run build`, `bun run start`, and `bun run dev`.

## `furin build`

```sh
furin build [options]
```

| Flag | Value | Default | Meaning |
|---|---|---|---|
| `--target` | `bun`, `vercel`, `cloudflare`, `static`, `package`, or `all` | `bun` | Select output |
| `--pagesDir` | Path | Config or auto-detected | Build one explicit app |
| `--prefix` | URL prefix | `""` | Prefix paired with the explicit pages directory |
| `--config` | Path | Auto-discovered | Use another config file |
| `--compile` | `server` or `embed` | No executable; inherits `bun.compile` when configured | Produce a Bun executable |
| `--analyze` | Boolean flag | `false` | Write Bun metafiles under `.furin/build/analysis` |

`--compile` without a value means `server`; `--compile=embed` is also accepted.

```sh
# Bundled Bun server
furin build --target bun

# Executable plus assets on disk
furin build --target bun --compile server

# One self-contained executable
furin build --target bun --compile embed

# Cloudflare Workers with CDN assets
furin build --target cloudflare

# Pure static output
furin build --target static

# Publishable Furin/Elysia plugin
furin build --target package --pagesDir ./src/admin --prefix /admin

# Bun, Vercel, and static outputs
furin build --target all
```

`all` preserves the deploy targets `bun`, `vercel`, and `static`. It excludes `package`, which is an alternative packaging of one app, and the initial `cloudflare` target, which must be selected explicitly because its runtime has a narrower feature set.

### Target Status

| Target | Status | Main output |
|---|---|---|
| `bun` | Implemented | `.furin/build/bun` |
| `static` | Implemented | `static.outDir`, default `dist` |
| `package` | Implemented | `.furin/build/package` |
| `vercel` | Implemented | `.vercel/output` (Bun Function, CDN assets, native SSG/ISR) |
| `cloudflare` | SSR/SSG; no ISR, PPR, RSC, or Sync | `.furin/build/cloudflare` (Worker, Wrangler config, CDN assets) |

Every successful build writes `.furin/build/manifest.json`. It records route modes, app prefixes, output paths, build IDs, and target-specific metadata.

### Analyze Output

`--analyze` writes Bun metafiles for client builds and the Bun, Vercel, and Cloudflare server builds. Cloudflare emits both `cloudflare-client.json` and `cloudflare-server.json`. Analysis stays outside the public asset directory. These graphs describe emitted byte sizes and import contributions, but do not measure startup latency, request throughput, memory, or edit-to-paint time.

## `furin preview`

Serve a completed static export locally:

```sh
furin preview [options]
```

| Flag | Default | Meaning |
|---|---|---|
| `--dir` | `static.outDir` or `dist` | Directory to serve |
| `--basePath` | `static.basePath` or `""` | Hosting prefix to simulate |
| `--port` | `3000` | Local TCP port |
| `--config` | Auto-discovered | Alternate config file |

```sh
furin build --target static
furin preview --port 4173
```

Preview handles clean HTML routes and the generated `404.html` fallback. It is a validation server, not a production application runtime.

## Development

```sh
bun --hot src/server.ts
```

The scaffolder maps that command to `bun run dev`. Route discovery, generated types, React Fast Refresh, server re-imports, diagnostics, and DevTools are activated by `furin()` in development; there is no separate `furin dev` command.
