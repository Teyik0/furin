# CLI Reference

The Furin CLI develops, builds production artifacts, previews static exports and generates route types.

```sh
furin help
furin dev
furin build
furin preview
furin typegen
```

Generated projects map `bun run dev` to `bun --hot src/server.ts`, `bun run build` to `furin build --target bun --compile embed`, and `bun run start` to the built `.furin/build/bun/server` executable.

## `furin dev`

```sh
furin dev [--web | --desktop] [--port number]
```

Development runs the configured server entry (`serverEntry`, default `src/server.ts`) with Bun hot reloading. The entry keeps ownership of its listener: call `.listen()` in it as usual, and Furin honors its hostname, TLS, port, and Elysia start/stop hooks.

| Flag | Meaning |
|---|---|
| `--port` | Override the source listener's port (or `PORT`). In desktop projects, only valid with `--web` |
| `--web` | Web mode: skip any native desktop integration |
| `--desktop` | Desktop mode: start the native app without opening a browser owner session |

Rules:

- Without flags, a project with `desktop` in `furin.config.ts` starts the [native desktop app](/docs/desktop) and also opens an authenticated owner session in the system browser. Projects without `desktop` run the source entry directly.
- `--web` forces web-only development, even in a desktop project. It never initializes the Electrobun SDK.
- An entry that only default-exports its application is still supported: `furin dev` starts it on `127.0.0.1:3000` (or the `--port` value).
- Application errors report through the [development overlay](/docs/dev-hmr); startup is cancelled after 30 seconds.

Web hot replacement always re-imports the source graph after `app.stop(true)`, so release exclusive resources in `.onStop()`.

## `furin build`

```sh
furin build [options]
```

| Flag | Value | Default | Meaning |
|---|---|---|---|
| `--target` | `bun`, `vercel`, `static`, `package`, `all`, or a configured adapter name | Every config `targets` entry, else `bun` | Select output |
| `--pagesDir` | Path | Config or auto-detected | Build one explicit app |
| `--prefix` | URL prefix | `""` | Prefix paired with the explicit pages directory |
| `--config` | Path | Auto-discovered | Use another config file |
| `--compile` | `server` or `embed` | No executable; inherits `bun.compile` when configured | Produce a Bun executable |
| `--output` | `app` or `server` | `server`, or `bun.output` when configured | Bun only: `app` emits an inert `app.js` without a listener entry (not combinable with `--compile`), `server` emits a bootable `server.js` |
| `--external` | Package name (repeatable) | None | Bun only: package to keep external in the server and RSC bundles |
| `--analyze` | Boolean flag | `false` | Write client and server Bun metafiles under `.furin/build/analysis` |

`--compile` without a value means `server`; `--compile=embed` is also accepted.

```sh
# Bundled Bun server
furin build --target bun

# Executable plus assets on disk
furin build --target bun --compile server

# One self-contained executable
furin build --target bun --compile embed

# Pure static output
furin build --target static

# Publishable Furin/Elysia plugin
furin build --target package --pagesDir ./src/admin --prefix /admin

# Bun, Vercel, and static outputs
furin build --target all
```

`all` means the deploy targets `bun`, `vercel`, and `static`; it deliberately excludes `package`, which is an alternative packaging of one app. A `--target` name that matches an entry of the config `targets` builds that entry, with its adapter options.

### Target Status

| Target | Status | Main output |
|---|---|---|
| `bun` | Implemented | `.furin/build/bun` |
| `static` | Implemented | `static.outDir`, default `dist` |
| `package` | Implemented | `.furin/build/package` |
| `vercel` | Implemented | `.vercel/output` (Bun Function, CDN assets, native SSG/ISR) |

Every successful build writes `.furin/build/manifest.json`. It records route modes, app prefixes, output paths, build IDs, and target-specific metadata.

### Analyze Output

`--analyze` writes one client metafile per mounted app (for example `bun-client.json` and `bun-client-admin.json`) plus the target's server metafile (`bun-server.json`). They describe emitted byte sizes and import contributions, but do not measure startup latency, request throughput, memory, or edit-to-paint time.

## `furin typegen`

Write `furin-env.d.ts` without starting or building the app, for example before `tsc` in CI:

```sh
furin typegen [options]
```

| Flag | Default | Meaning |
|---|---|---|
| `--pagesDir` | Config `pagesDir`, config `apps`, `furin()` mounts of the evaluated server entry, then `src/pages` | Pages directory of the root-mounted app |
| `--config` | Auto-discovered | Alternate config file |

It writes the same file as the development server and `furin build`: `FileRoutes` covers the route files of every mounted app, and `RouteMap` the patterns of the root-mounted app (prefix `""`).

## `furin preview`

Serve a completed static export locally:

```sh
furin preview [options]
```

| Flag | Default | Meaning |
|---|---|---|
| `--dir` | `static.outDir` or `dist` | Directory to serve |
| `--basePath` | `static.basePath` or `""` | Hosting prefix to simulate |
| `--port` | `3000` | Local TCP port |
| `--config` | Auto-discovered | Alternate config file |

```sh
furin build --target static
furin preview --port 4173
```

Preview handles clean HTML routes and the generated `404.html` fallback. It is a validation server, not a production application runtime.

## Development Without The CLI

```sh
bun --hot src/server.ts
```

This is what `bun run dev` runs in generated projects. Route discovery, `furin-env.d.ts` generation, React Fast Refresh, server re-imports, diagnostics, and DevTools are activated by `furin()` itself, so both workflows get them. `furin dev` adds entry resolution from the config, a `--port` override, a fallback listener for entries that only default-export their app, and desktop mode selection. In desktop projects, direct `bun --hot` uses the [desktop preload](/docs/desktop/installation#initialize) registered in `bunfig.toml` instead.
