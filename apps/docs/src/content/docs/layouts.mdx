# Nested Layouts

Layouts share UI and loader data across a filesystem branch. `root.tsx` owns the document; each `_route.tsx` wraps the pages and deeper layouts in its directory.

## Root Document

Every pages directory requires `root.tsx`:

```tsx
// src/pages/root.tsx
import { defineRootRoute, HeadContent, Scripts } from "@teyik0/furin";
import "./globals.css";

export const route = defineRootRoute()
  .config({ mode: "ssg" })
  .layout(({ children }) => (
    <html lang="en">
      <head>
        <HeadContent />
      </head>
      <body>
        {children}
        <Scripts />
      </body>
    </html>
  ));
```

Furin does not add a second document shell. Omitting `<HeadContent />` or `<Scripts />` makes the root invalid because metadata, serialized data, framework clients, and the hydration entry need those insertion points.

## Directory Layouts

```tsx
// src/pages/dashboard/_route.tsx
import { defineRoute } from "@teyik0/furin";
import { route as rootRoute } from "../root";

export const route = defineRoute()
  .config({ layout: rootRoute, mode: "ssr" })
  .loader(async ({ request }) => ({ user: await getSession(request) }))
  .layout(({ children, data }) => (
    <div className="dashboard-shell">
      <DashboardNav user={data.user} />
      <main>{children}</main>
    </div>
  ));
```

A page in that directory points to the layout terminal:

```tsx
// src/pages/dashboard/settings.tsx
import { defineRoute } from "@teyik0/furin";
import { route as dashboardRoute } from "./_route";

export const route = defineRoute()
  .config({ layout: dashboardRoute, mode: "ssr" })
  .loader(async ({ user }) => {
    const sessionUser = await user;
    return { settings: await getSettings(sessionUser.id) };
  })
  .page(({ data }) => <Settings user={data.user} value={data.settings} />);
```

Ancestor data is merged into descendant component `data`. In descendant loaders, each ancestor field is an individual promise, so unrelated work can start in parallel and a child only awaits what it needs.

## Multiple Levels

```text
src/pages/
├── root.tsx
└── dashboard/
    ├── _route.tsx
    └── account/
        ├── _route.tsx
        └── security.tsx
```

Each module references its immediate parent. The explicit import exists for TypeScript inference; the filesystem remains the routing authority. Furin reports or repairs a `layout` reference that disagrees with the directory tree.

Do not skip a parent to reuse an unrelated layout. Extract ordinary React components for visual reuse and keep route layouts aligned with URL ownership.

## Rendering Modes Across A Chain

Each layout and page declares a mode, while the resolved page owns the final request strategy. Cached routes cannot use request-bound values in public loaders. When a cached branch needs per-request personalization, keep the cacheable data in `loader()` and move cookies or headers to `requestLoader()`; see [Rendering Modes](/docs/rendering).

Deferred fields also flow through layouts. Render them with `<Await>` inside `<Suspense>` exactly as you would in a page; see [Deferred Data](/docs/defer).
