# Nested Layouts

Furin uses `_route.tsx` files for directory layouts. Every route module exports one named `route` terminal; filesystem nesting determines how those terminals compose.

## Root Layout

`src/pages/root.tsx` is required and owns `<html>` and `<body>`. Place `<HeadContent />` in `<head>` and `<Scripts />` at the end of `<body>`; Furin does not inject a second document shell.

```tsx
// src/pages/root.tsx
import { defineRootRoute, HeadContent, Scripts } from "@teyik0/furin"

export const route = defineRootRoute()
  .config({ mode: "ssr" })
  .layout(({ children }) => (
    <html lang="en">
      <head>
        <HeadContent />
      </head>
      <body>
        {children}
        <Scripts />
      </body>
    </html>
  ))
```

## Directory Layout

```tsx
// src/pages/blog/_route.tsx
import { defineRoute } from "@teyik0/furin"
import { route as rootRoute } from "../root"

export const route = defineRoute()
  .config({ layout: rootRoute, mode: "ssr" })
  .layout(({ children }) => (
    <div className="mx-auto max-w-5xl px-4 py-10">
      <BlogSidebar />
      <main>{children}</main>
    </div>
  ))
```

Pages create their own route terminal. They do not extend or mutate the layout instance.

```tsx
// src/pages/blog/index.tsx
import { defineRoute } from "@teyik0/furin"
import { route as parentRoute } from "./_route"

export const route = defineRoute()
  .config({ layout: parentRoute, mode: "ssr" })
  .page(() => <BlogList />)
```

## Multi-Level Nesting

```text
src/pages/
├── root.tsx
├── docs/
│   ├── _route.tsx
│   └── advanced/
│       ├── _route.tsx
│       └── plugins.tsx
```

Each child `_route.tsx` names its parent in `config({ layout })` for loader-data inference. The route generator mounts the child under its filesystem parent, so Elysia's local scope flows downward.

## Layout Data

```tsx
// src/pages/dashboard/_route.tsx
import { defineRoute } from "@teyik0/furin"
import { route as rootRoute } from "../root"

export const route = defineRoute()
  .config({ layout: rootRoute, mode: "ssr" })
  .loader(async ({ request }) => ({
    user: await getSession(request),
  }))
  .layout(({ children, data: { user } }) => (
    <div>
      <DashboardNav user={user} />
      {children}
    </div>
  ))
```

Descendant components receive merged loader data under `data`. Descendant loaders receive ancestor fields as promises and await only what they need.

## Deferred Layout Data

```tsx
// src/pages/dashboard/_route.tsx
import { defineRoute } from "@teyik0/furin"
import { Await, defer } from "@teyik0/furin/client"
import { Suspense } from "react"
import { route as rootRoute } from "../root"

export const route = defineRoute()
  .config({ layout: rootRoute, mode: "ssr" })
  .loader(() =>
    defer({
      user: "alice",
      widgets: fetchSidebarWidgets(),
    })
  )
  .layout(({ children, data: { user, widgets } }) => (
    <div>
      <nav>Hello {user}</nav>
      <Suspense fallback={<WidgetSkeleton />}>
        <Await resolve={widgets}>{(list) => <WidgetList items={list} />}</Await>
      </Suspense>
      <main>{children}</main>
    </div>
  ))
```

See [Deferred Data Streaming](/docs/defer) for the full API.
