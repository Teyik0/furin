# Multi-Instance & Packaged Apps

One Elysia server can mount several Furin page trees. Each instance has a unique prefix and owns its route graph, client assets, document template, build ID, render caches, framework endpoints, and not-found behavior.

```ts
import { Elysia } from "elysia";
import { furin } from "@teyik0/furin";

new Elysia()
  .use(await furin({ pagesDir: "./src/pages" }))
  .use(await furin({ pagesDir: "./src/admin", prefix: "/admin" }))
  .listen(3000);
```

```text
src/pages/index.tsx       → /
src/pages/blog.tsx        → /blog
src/admin/index.tsx       → /admin
src/admin/users.tsx       → /admin/users
```

## Prefix Rules

- The root instance uses `""` or `/`.
- A non-root prefix starts with `/` and has no trailing slash after normalization.
- Two instances cannot claim the same prefix.
- Prefixes that would produce the same client-directory slug are also rejected.

Everything an instance owns is physically prefixed: pages, `/_furin/*` endpoints, `/_client/*`, `/public/*`, and the favicon.

Inside the pages tree, URLs stay logical:

```tsx
// src/admin/index.tsx
<Link to="/users">Users</Link>
```

The admin bundle renders `/admin/users` and sends route-data requests below `/admin`. Keep page code independent of its deployment prefix.

Use a plain anchor for navigation between separate Furin instances:

```tsx
<a href="/admin">Open admin</a>
```

That intentionally loads the other document and browser bundle.

## Isolation And Shared Operations

| Concern | Behavior |
|---|---|
| SSG, ISR, PPR, and dev loader caches | Per instance |
| Build ID and document template | Per instance |
| Root/prefixed 404 handling | Per instance |
| `revalidatePath()` | Applies the logical path across all mounted instances |
| `revalidateTag()` | Finds tagged paths across instances, then evicts only from each owner |
| Sync journal | Determined by the configured adapter and namespace |
| CDN purge paths | Converted to physical prefixed URLs |

Cross-instance path and tag invalidation is deliberate for applications sharing data. If two apps use the same logical path for unrelated content, prefer distinct tags and avoid broad path invalidation.

## Build Discovery

Furin can statically detect literal mounts in `server.ts`. Declare dynamic mounts explicitly when values come from variables or factories:

```ts
// furin.config.ts
import { defineConfig } from "@teyik0/furin/config";

export default defineConfig({
  apps: [
    { pagesDir: "./src/pages" },
    { pagesDir: "./src/admin", prefix: "/admin" },
  ],
});
```

The Bun target produces one client directory per app and one server artifact. Static export selects the root-mounted app only. In development, the root app owns the single generated `furin-env.d.ts`; cross-instance links are therefore intentionally not one combined typed SPA route map.

## Packaged Furin Apps

The `package` target builds one page tree as a publishable Elysia plugin:

```sh
furin build --target package --pagesDir ./src/pages --prefix /admin
```

`.furin/build/package` contains:

- `client/`: content-hashed browser assets and the document template;
- `public/`: copied public assets when present;
- `register.js`: bundled page modules and compile-context registration;
- `index.js` and `index.d.ts`: the `createFurinApp()` factory.

Dependencies stay external so the host and packaged app share one Furin runtime.

```ts
import { Elysia } from "elysia";
import { createFurinApp as createAdminApp } from "@org/admin/furin";
import { furin } from "@teyik0/furin";

new Elysia()
  .use(await furin({ pagesDir: "./src/pages" }))
  .use(await createAdminApp())
  .listen(3000);
```

The factory bakes in `pagesDir`, `prefix`, and `clientDir`; the host may still pass logger or sync options. In a monorepo with sources present it supports live development. A published artifact without page sources is production-only.

`--compile embed` on the host does not currently re-embed a packaged app's client directory. Prefer a disk-mode host when composing packaged apps into one process.
