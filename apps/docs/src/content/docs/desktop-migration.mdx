# Migrating To Furin Desktop

This page maps an existing standalone Electrobun (tofu-style) application onto Furin's desktop integration. The reference application for these notes kept its business API, pages, and data in one Elysia app and drove window lifecycle through ad-hoc HTTP endpoints and native callbacks. Nothing in that checkout is modified by this integration; these are the replacement moves.

## Declare Windows On The Elysia Root

Replace window construction wherever it scattered — native entrypoints, launch scripts, controller bootstraps — with one plugin install on the root application:

```ts
const app = new Elysia({ name: "relay" })
  .use(
    desktopApp({
      window: {
        title: "Relay",
        frame: { width: 1100, height: 780 },
        titleBarStyle: "hiddenInset",
        renderer: "native",
      },
      restrictWebToLoopback: true,
    })
  )
  .use(api)
  .use(await furin({ pagesDir: `${import.meta.dir}/pages` }))
  .listen({ hostname: "127.0.0.1", port: 4242 });
```

Independent API plugins keep typed access through `desktopContext` without re-declaring a root. Native code reaches the same controller through `getDesktopHost()`.

## Move Application Lifecycle Into Elysia Hooks

Application data/profile initialization and disposal belong to `.onStart()` and `.onStop()`, not to native boot code. Keep dependent startup steps in one async hook so Elysia owns cleanup:

```ts
.onStart(async () => {
  await profile.open();
})
.onStop(async () => {
  await profile.close();
})
```

Native events must handle their own errors. Request errors stay in `.onError()`.

## Replace `onOpen` Callbacks With SDK Events

There is no Furin `onOpen` option or native-module export contract. Subscribe to the original SDK event inside `desktop.build.bun.entrypoint`:

```ts
import { Electrobun } from "electrobun/main";

Electrobun.events.on("open-url", (event) => {
  // event.data.url is a URL; associated files arrive as file: URLs
});
```

Declare schemes and file associations in `desktop.app.urlSchemes` / `desktop.app.fileAssociations`. Furin forwards launch inputs and secondary-instance inputs to this event after host readiness; direct OS events follow the SDK lifecycle. Coordinate any application startup dependency inside the handler when needed.

## Keep Existing Data Directories Working

Declare a runtime `dataDir` policy instead of packaging a path: resolve the user environment at launch, not during packaging. Existing profile markers, business input handling, and data migrations remain application-owned — the host only resolves and shares the directory.

```ts
dataDir: { name: "relay", developmentName: "relay-dev" },
```

## Convert UI Native Actions To `useDesktop()`

For React UI actions, use `useDesktop()` from `@teyik0/furin-electrobun/client` instead of checking the backend runtime or calling a native action over HTTP. The typical replacement:

- Delete `POST /api/updates/open-download` and callers of it.
- Render a normal anchor in web/SSR; when `desktop.status === "desktop"`, intercept the click and call `desktop.browser.open(downloadUrl)`.
- Keep `GET /api/updates/download` solely to serve the file.

```tsx
onClick={(event) => {
  if (desktop.status !== "desktop") return;
  event.preventDefault();
  void desktop.browser.open("/api/updates/download");
}}
```

Remember the authentication limits from [Desktop Client](/docs/desktop/client#download-link-with-desktop-behavior): opening a URL never transfers the webview session to the system browser, so a private loopback download URL may need its own application-owned delivery flow.

## Map Remaining Native Surfaces

| Tofu-era surface | Furin replacement |
|---|---|
| Manual window construction in native code | `desktopApp({ window: {...} })` on the root |
| Secondary windows built by hand | `desktop.windows.create(name, { path, ... })` with managed authentication |
| Custom quit handlers per window | `desktop.quit()` / `desktop.restart()` coordinated drains |
| App-menu wiring in backend code | `ApplicationMenu` in the native entrypoint; `getDesktopHost()` for actions |
| Background/keep-alive flags | `background` policy on `desktopApp` |
| Update install flows | `desktop.updates.install()` with backend drain before SDK handoff |

SDK menus, tray, dialogs, notifications, shortcuts, screens, sessions, views, RPC, and GPU capabilities remain available through `electrobun/main` and its original public subpaths — nothing stops you from keeping those pieces as-is.
