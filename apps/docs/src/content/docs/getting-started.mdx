# Getting Started

Furin is a React meta-framework built on Elysia and Bun. It gives you file-based routing, SSR, SSG, ISR, nested layouts, and typed route data without a separate frontend toolchain.

## Create A Project

```bash
bun create furin@latest my-app
cd my-app
bun dev
```

For the shadcn/ui starter:

```bash
bun create furin@latest my-app --template full
cd my-app
bun dev
```

## Available Templates

- `simple` — Tailwind CSS + `/api/hello` route + SSR page loader (default)
- `full` — everything in `simple` plus shadcn/ui components (`button`, `card`, `input`)

## Project Shape

```text
my-app/
├── src/
│   ├── pages/
│   │   ├── root.tsx
│   │   └── index.tsx
│   ├── api/
│   └── server.ts
├── furin.config.ts
├── bunfig.toml
└── package.json
```

## First Server

```ts
// src/server.ts
import { Elysia } from "elysia"
import { furin } from "@teyik0/furin"

const app = new Elysia()
  .use(await furin({ pagesDir: "./src/pages" }))
  .listen(3000)

export type App = typeof app
```

## Root Layout

Every app needs `src/pages/root.tsx`. It owns the complete document. `<HeadContent />` renders framework assets and route metadata; `<Scripts />` renders the hydration bootstrap and must stay inside `<body>`.

```tsx
// src/pages/root.tsx
import { defineRootRoute, HeadContent, Scripts } from "@teyik0/furin"

export const route = defineRootRoute()
  .config({ mode: "ssr" })
  .layout(({ children }) => (
    <html lang="en">
      <head>
        <HeadContent />
      </head>
      <body>
        {children}
        <Scripts />
      </body>
    </html>
  ))
```

## First Page

```tsx
// src/pages/index.tsx
import { defineRoute } from "@teyik0/furin"
import { route as rootRoute } from "./root"

export const route = defineRoute()
  .config({ layout: rootRoute, mode: "ssr" })
  .page(() => <h1>Hello Furin</h1>)
```

## Development

```bash
bun run dev
```

The docs app and starters run Bun directly in development, so backend and frontend stay in the same process.

You can also create empty route files and let development mode scaffold the smallest valid builder:

- `pages/root.tsx` becomes an SSR root layout.
- `pages/**/_route.tsx` becomes an SSR layout linked to its nearest ancestor layout.
- Any other route file becomes an SSG page linked to its nearest ancestor layout.

Non-empty helper files stay untouched. A route file must export exactly one builder as
`export const route`, and its terminal must match its filename: `_route` uses `.layout()`, while
normal route files use `.page()`. Ambiguous layouts and contradictory rendering options fail at
boot and are reported again by the development watcher with the file path and required action.
