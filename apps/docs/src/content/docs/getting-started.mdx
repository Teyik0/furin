# Getting Started

Create a Furin application with Bun:

```sh
bun create furin@latest my-app
cd my-app
bun run dev
```

The interactive scaffolder offers two templates:

| Template | Includes |
|---|---|
| `simple` | Tailwind CSS and an Elysia API route |
| `full` | The simple stack plus shadcn/ui components |

Choose one without a prompt when scripting:

```sh
bun create furin@latest my-app --template simple --yes
```

## Project Structure

Both templates produce the same framework shape:

```text
my-app/
├── public/
│   └── favicon.ico
├── src/
│   ├── api/
│   │   └── hello.ts
│   ├── pages/
│   │   ├── globals.css
│   │   ├── index.tsx
│   │   └── root.tsx
│   └── server.ts
├── bunfig.toml
├── furin.config.ts
├── furin-env.d.ts
└── tsconfig.json
```

- `src/server.ts` composes the Elysia application.
- `src/pages/root.tsx` owns the HTML document shared by every page.
- `src/pages/index.tsx` maps to `/`.
- `furin.config.ts` controls production builds.
- `bunfig.toml` registers the client-side Bun plugins used by development.
- `furin-env.d.ts` is generated from the route tree and should not be edited manually.

## The Server

Furin is an Elysia plugin, so pages and APIs compose through `.use()`:

```ts
// src/server.ts
import { Elysia } from "elysia";
import { furin } from "@teyik0/furin";
import { api } from "./api/hello";

new Elysia()
  .use(await furin({ pagesDir: "./src/pages" }))
  .use(api)
  .listen(3000);
```

Keep chaining the returned Elysia instance. Plugin order and lifecycle scope remain Elysia concerns; see [API Routes](/docs/api-routes).

## The Root Document

Every pages directory needs `root.tsx`. It must render a complete document containing `<HeadContent />` and `<Scripts />`:

```tsx
// src/pages/root.tsx
import { defineRootRoute, HeadContent, Scripts } from "@teyik0/furin";
import "./globals.css";

export const route = defineRootRoute()
  .config({ mode: "ssg" })
  .layout(({ children }) => (
    <html lang="en">
      <head>
        <HeadContent />
      </head>
      <body>
        {children}
        <Scripts />
      </body>
    </html>
  ));
```

`<HeadContent />` renders framework assets and the matched page's metadata. `<Scripts />` serializes route state and loads the browser entry.

## Your First Page

Every non-root route references its parent layout explicitly:

```tsx
// src/pages/index.tsx
import { defineRoute } from "@teyik0/furin";
import { route as rootRoute } from "./root";

export const route = defineRoute()
  .config({ layout: rootRoute, mode: "ssg" })
  .head(() => ({ meta: [{ title: "Home" }] }))
  .page(() => <h1>Hello, Furin</h1>);
```

During development, Furin verifies that `layout` matches the filesystem hierarchy and can repair missing or misplaced imports. Treat the generated correction as the canonical shape rather than fighting the route tree.

## Development And Production

```sh
# Bun dev server with React Fast Refresh
bun run dev

# Check formatting and types, then build
bun run fix
bun run tscheck
bun run build

# Run the built Bun server
bun run start
```

The scaffold's `dev` script starts `src/server.ts` with Bun hot reloading. If you add, remove, or move a page, the route manifest and `furin-env.d.ts` are refreshed automatically.
