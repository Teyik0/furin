# Getting Started

Create a Furin application with Bun:

```sh
bun create furin@latest my-app
cd my-app
bun run dev
```

The interactive scaffolder offers two templates:

| Template | Includes |
|---|---|
| `simple` | Tailwind CSS and an Elysia API route |
| `full` | The simple stack plus shadcn/ui components |

Choose one without a prompt when scripting:

```sh
bun create furin@latest my-app --template simple --style tanstack --yes
```

The scaffolder also asks for a [routing style](/docs/routing), or takes it from `--style`: `tanstack` (TanStack Start files in `src/routes`) or `nextjs` (Next.js App Router files in `src/app`).

## Project Structure

Both templates produce the same framework shape. With the `tanstack` style:

```text
my-app/
├── public/
│   └── favicon.ico
├── src/
│   ├── api/
│   │   └── hello.ts
│   ├── routes/
│   │   ├── globals.css
│   │   ├── index.tsx
│   │   └── __root.tsx
│   └── server.ts
├── biome.jsonc
├── bunfig.toml
├── furin.config.ts
├── furin-env.d.ts
├── package.json
├── README.md
└── tsconfig.json
```

With the `nextjs` style, `src/routes/__root.tsx` and `src/routes/index.tsx` are `src/app/layout.tsx` and `src/app/page.tsx`. `full` also adds `components.json`, `src/components/ui/` and `src/lib/utils.ts` for shadcn/ui.

- `src/server.ts` composes the Elysia application.
- `src/routes/__root.tsx` (`src/app/layout.tsx`) owns the HTML document shared by every page.
- `src/routes/index.tsx` (`src/app/page.tsx`) maps to `/`.
- `furin.config.ts` controls production builds.
- `bunfig.toml` registers the client-side Bun plugins used by development.
- `furin-env.d.ts` holds the [generated route types](/docs/routing#generated-route-types); do not edit it. Despite its name, it does not type environment variables: it types `<Link to>`, `navigate()`, route params and `getRouteApi()` from your pages, and references Furin's ambient types for CSS and image imports. The dev server, `furin build` and `furin typegen` rewrite it.

## The Server

Furin is an Elysia plugin, so pages and APIs compose through `.use()`:

```ts
// src/server.ts
import { furin } from "@teyik0/furin";
import { Elysia } from "elysia";
import { initLogger } from "evlog";
import { getHelloPayload } from "./api/hello";

initLogger({ env: { service: "my-app" } });

const app = new Elysia()
  .get("/api/hello", () => getHelloPayload())
  .use(await furin({ style: "tanstack" }));

export const port = Number(process.env.PORT ?? 3000);

if (import.meta.main) {
  app.listen(port);
  console.log(`my-app running at http://localhost:${app.server?.port}`);
}

export default app;
```

`style` is required and selects the file convention; each style reads its conventional directory unless you pass `pagesDir`. Keep chaining the returned Elysia instance. Plugin order and lifecycle scope remain Elysia concerns; see [API Routes](/docs/api-routes). `initLogger()` configures [evlog](/docs/logging), which backs the `log` available in loaders.

## The Root Document

Every pages directory needs a root document: `__root.tsx` in the TanStack style, a top-level `layout.tsx` in the Next.js style. It must render a complete document containing `<HeadContent />` and `<Scripts />`:

```tsx
// src/routes/__root.tsx (or src/app/layout.tsx)
import { defineRootRoute, HeadContent, Scripts } from "@teyik0/furin";
import "./globals.css";

export const route = defineRootRoute()
  .config({ mode: "ssg" })
  .layout(({ children }) => (
    <html lang="en">
      <head>
        <HeadContent />
      </head>
      <body>
        {children}
        <Scripts />
      </body>
    </html>
  ));
```

`<HeadContent />` renders framework assets and the matched page's metadata. `<Scripts />` serializes route state and loads the browser entry.

## Your First Page

Every non-root route passes its file's id to `defineRoute(id)`. The id gives the route its parent layout's types; see [Route Ids](/docs/routing#route-ids):

```tsx
// src/routes/index.tsx (or src/app/page.tsx)
import { defineRoute } from "@teyik0/furin";

export const route = defineRoute("/")
  .config({ mode: "ssg" })
  .head(() => ({ meta: [{ title: "Home" }] }))
  .page(() => <h1>Hello, Furin</h1>);
```

Create a route file empty and the development server writes a starter route with its id. Furin never rewrites a file that has content: a missing or stale id is reported in the terminal and the error overlay, with the exact `defineRoute(...)` call to write.

## Development And Production

```sh
# Bun dev server with React Fast Refresh
bun run dev

# Fix lint and formatting, check types, then build
bun run fix
bun run tscheck
bun run build

# Run the compiled server executable
bun run start
```

The scaffold's `dev` script runs `bun --hot src/server.ts`. Adding, removing or moving a page refreshes the route manifest and `furin-env.d.ts` automatically. `build` runs `furin build --target bun --compile embed`, which writes a single executable to `.furin/build/bun/server`; see [Deployment](/docs/deployment).

> [!TIP]
> `bunx --bun furin dev` is the CLI companion of that script. It resolves the configured entry, honors its listener, and can start the [native desktop app](/docs/desktop) in desktop projects. See the [CLI Reference](/docs/cli#furin-dev).
