# Configuration Reference

The `furin` CLI reads the first `furin.config.ts`, `furin.config.js`, or `furin.config.mjs` in the working directory, or the file passed to `--config` with `build`, `preview`, and `typegen`. `defineConfig()` provides inference; Furin validates the file when the CLI loads it. Unknown keys fail with their path and the closest valid key (for example, `reactCompilor` suggests `reactCompiler`), every plugin must be an object with a `name` string and a `setup` function, and every target must be a built-in name or a deployment adapter.

```ts
// furin.config.ts
import { vercel } from "@teyik0/furin/adapters/vercel";
import { defineConfig } from "@teyik0/furin/config";
import tailwind from "bun-plugin-tailwind";

export default defineConfig({
  rootDir: ".",
  pagesDir: "src/pages",
  serverEntry: "src/server.ts",
  clientLogging: false,
  reactCompiler: true,
  plugins: [{ ...tailwind, buildOnly: true }],
  bun: { compile: "embed" },
  targets: ["bun", vercel({ regions: ["cdg1"] })],
});
```

CLI flags override the corresponding file settings. Paths are resolved from the CLI working directory, then `pagesDir` and `serverEntry` are resolved relative to `rootDir`.

## Build Fields

| Field | Type | Default | Purpose |
|---|---|---|---|
| `rootDir` | `string` | Current directory | Project root for build paths |
| `pagesDir` | `string` | Detected mounts, then `src/pages` | Pages directory for one root-mounted app |
| `serverEntry` | `string` | `src/server.ts` | Elysia entry for server builds |
| `apps` | `{ pagesDir; prefix? }[]` | Auto-detected | Explicit multi-instance build inputs |
| `clientLogging` | `boolean` | `false` | Include the browser evlog HTTP drain |
| `reactCompiler` | `boolean` | `true` | Enable Bun's React compiler in client builds |
| `optimizeImports` | `string[]` | Bun defaults | Extra package barrels for Bun import optimization |
| `plugins` | `FurinPlugin[]` | None | Bun build and route-import plugins |
| `preload.routeChunks` | `boolean` | `true` | Emit `<link rel="modulepreload">` for the current route's chunks |
| `bun.compile` | `"server" \| "embed"` | No executable | Compile the Bun server |
| `bun.output` | `"app" \| "server"` | `server` | Emit a bootable `server.js` or an inert, importable `app.js` (same as `--output`) |
| `serverSourceMaps` | `boolean` | `false` | Emit private server source maps (see [Deployment](/docs/deployment#private-server-source-maps-and-error-tools)) |
| `desktop` | Object | None | Native desktop integration, validated by `@teyik0/furin-electrobun` (see [Desktop](/docs/desktop)) |
| `static` | `StaticExportConfig` | See below | Configure pure static output |
| `targets` | `(BuildTarget \| FurinAdapter)[]` | `["bun"]` | What `furin build` builds without `--target`; also where adapters receive their options |

`apps` takes precedence over `pagesDir`, which takes precedence over the server entry. When neither is configured, the build evaluates the server entry in a child process, where `furin()` only records its `{ pagesDir, prefix }`, and builds those apps; without any recorded mount it falls back to `src/pages`. Any `furin()` call counts, whatever its import name or how its options are computed. Relative `pagesDir` values resolve against `rootDir`.

Server builds then check the result against the application: Elysia AOT evaluates the server entry again, and a mounted app the build did not produce, or a built app the server never mounts, fails the build and lists both sides. Applications using `.mount()` skip AOT and therefore this check.

```ts
export default defineConfig({
  apps: [
    { pagesDir: "./src/pages" },
    { pagesDir: "./src/admin", prefix: "/admin" },
  ],
});
```

List the apps in `apps` when the server entry cannot be evaluated at build time.

## Client Logging

```ts
export default defineConfig({ clientLogging: true });
```

This includes `evlog/http` in the production browser entry and sends browser events to the prefixed `/_furin/ingest` endpoint. In development, `furin({ clientLogging: true })` is enough. Server request logging is configured separately through `furin({ logger })`. See [Logging](/docs/logging).

## React Compiler And Import Optimization

```ts
export default defineConfig({
  reactCompiler: true,
  optimizeImports: ["legacy-ui-library"],
});
```

Bun's React compiler is enabled by default; disable it only to isolate a compiler incompatibility. Bun already optimizes packages declaring `sideEffects: false`, so list only additional pure barrel packages under `optimizeImports`.

## Plugins

```ts
import type { FurinPlugin } from "@teyik0/furin/config";

const assetPlugin: FurinPlugin = {
  name: "asset-plugin",
  buildOnly: true,
  setup(build) {
    // Register Bun build hooks.
  },
};
```

Production registers non-`buildOnly` plugins while importing routes, then forwards every plugin to the relevant Bun builds. Development client plugins live in `bunfig.toml`; server-side route imports may also require `Bun.plugin()`. See [Plugins](/docs/plugins).

## Bun Executables

```ts
export default defineConfig({ bun: { compile: "server" } });
```

| Value | Output |
|---|---|
| Omitted | Bundled `server.js` with assets on disk |
| `server` | Native executable with client/public assets on disk |
| `embed` | Native executable with framework client/public assets embedded |

The CLI `--compile` flag wins over this field.

## Targets And Adapters

```ts
import { vercel } from "@teyik0/furin/adapters/vercel";

export default defineConfig({
  targets: ["bun", vercel({ regions: ["cdg1"] })],
});
```

`furin build` builds every entry of `targets`. `furin build --target vercel` builds the configured entry named `vercel`, so its options apply; a name missing from `targets` uses the built-in target with default options.

`vercel({ regions })` places the Function close to the application's database or upstream service. The editor suggests [Vercel's supported compute regions](https://vercel.com/docs/regions#region-list); an empty list, duplicates, and unsupported codes fail while the configuration loads. See [Deployment](/docs/deployment#adapters) for the adapter contract.

## Static Export

```ts
export default defineConfig({
  static: {
    basePath: "/docs",
    outDir: "dist",
    onSSR: "error",
  },
});
```

| Field | Type | Default | Purpose |
|---|---|---|---|
| `basePath` | `string` | `""` | Hosting subpath, starting with `/` and without a trailing slash |
| `outDir` | `string` | `dist` | Static output directory |
| `onSSR` | `"error" \| "skip"` | `error` | Fail on SSR/ISR routes or omit them with warnings |

Static export also rejects `requestLoader()` and dynamic SSG pages without `staticParams()` when `onSSR` is `error`.

## Runtime `furin()` Options

Runtime options live beside Elysia composition, not in the build config:

```ts
await furin({
  pagesDir: "./src/pages",
  prefix: "/admin",
  clientDir: "./custom-client",
  clientLogging: true,
  logger: { exclude: ["/health"] },
  pageCache,
  sync,
});
```

| Field | Purpose |
|---|---|
| `pagesDir` | Runtime pages identity; defaults to `src/pages` |
| `prefix` | Full physical path of pages, framework endpoints, public assets, and client assets; the client bundle is built for it |
| `clientDir` | Override production client assets; build artifacts normally resolve this automatically |
| `clientLogging` | Enable the browser log drain in development and the `/_furin/ingest` endpoint; production browser bundles also need `clientLogging` in `furin.config.ts` |
| `logger` | Per-instance evlog middleware options; configure process-wide settings such as sampling with `initLogger()` in the server entry |
| `cachePurger` | CDN purge hook for this instance; receives its physical paths and takes precedence over `setCachePurger()` |
| `cacheTagPurger` | CDN purge hook for this instance's semantic cache tags; receives the tags passed to `revalidateTag()` and takes precedence over the deployment adapter's tag purger |
| `pageCache` | Optional shared store for SSG, ISR, and PPR public artifacts; when omitted, the process-local render caches are used |
| `sync` | Sync adapter, principal resolver, optional notifier, optional principal hash `secret`, and optional durable endpoint `path` |

Keep the same `pagesDir` and `prefix` between the build and runtime mount. `prefix` is the full physical path: mount Furin on an Elysia instance without its own prefix. Each `furin()` call serves one application. See [Multi-Instance](/docs/multi-instance) and [Sync & Invalidations](/docs/sync).

Omit `pageCache` for a single Bun process and on Vercel, whose adapter rejects it at initialization. For multiple Bun replicas, see [Caches And Replicas](/docs/deployment#caches-and-replicas) and [Caching](/docs/caching#shared-page-cache).
