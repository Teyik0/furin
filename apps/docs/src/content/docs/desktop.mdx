# Desktop Overview

`@teyik0/furin-electrobun` packages a Furin application as a native desktop app. Your React DOM pages, SSR, API routes, Eden client, and Sync code serve both web and desktop from one Bun main process, while Electrobun 2.0.2 owns the system-WebView windows.

The integration does not fork Furin rendering or introduce a second backend: the native window loads the same application over an authenticated loopback destination, and the same Elysia listener that serves browsers serves the webviews.

```ts
import { furin } from "@teyik0/furin";
import { desktopApp } from "@teyik0/furin-electrobun/server";
import { Elysia } from "elysia";

const app = new Elysia()
  .use(
    desktopApp({
      window: {
        title: "Relay",
        frame: { width: 1100, height: 780 },
        titleBarStyle: "hiddenInset",
        renderer: "native",
      },
      restrictWebToLoopback: true,
    })
  )
  .use(api)
  .use(await furin({ pagesDir: "src/pages" }))
  .listen({ hostname: "127.0.0.1", port: 4242 });

export default app;
```

Install the plugin before listening — otherwise `desktopApp()` throws — and keep the application as the default export.

## Install

```sh
bun add -d @teyik0/furin-electrobun
bunx --bun @teyik0/furin-electrobun init
```

`init` configures an existing project without overwriting anything:

- declares `desktop` in `furin.config.ts` when the file does not exist yet; with an existing config that lacks `desktop`, it asks you to add `desktop: defineDesktopConfig(...)` and rerun;
- adds `build:desktop` (`furin-electrobun build`) and a `dev` script (`bun --hot src/server.ts`) unless present;
- registers the dev launcher in `bunfig.toml`:

```toml
preload = ["@teyik0/furin-electrobun/preload"]
```

The generated config looks like this:

```ts
// furin.config.ts
import { defineConfig } from "@teyik0/furin/config";
import { defineDesktopConfig } from "@teyik0/furin-electrobun";

export default defineConfig({
  desktop: defineDesktopConfig({
    app: { name: "Relay", identifier: "local.furin.relay" },
    build: { mainProcess: "bun", bun: { entrypoint: "src/desktop.ts" } },
  }),
});
```

`app.identifier` must be reverse-domain style; `app.version` defaults to the consuming package version. `mainProcess` must stay `"bun"` — Furin's in-process backend is the main process; the generated host owns the Electrobun entry.

## Listener Configuration

Use Elysia's `.listen(...)` as the single source of truth. Web browsers and the webview connect to that same server in the same process.

```ts
const app = new Elysia()
  .use(desktopApp({ window: { title: "Relay" } }))
  .use(api)
  .listen({ hostname: "127.0.0.1", port: 4242 });
```

- Both web and desktop use the configured port; pass TLS options to `.listen(...)` for HTTPS.
- Builds capture listener options without opening a socket or running startup hooks, then the desktop host starts the built application with them.
- Shared startup work belongs in `.onStart()`.
- An entry that only default-exports its app remains supported: without a configured hostname or port the host uses `127.0.0.1` and a free port.
- Managed windows resolve the application's listener hostname, scheme and port. Wildcards map to their local destination (`0.0.0.0` → `127.0.0.1`, `::` → `[::1]`); explicit hostnames, including LAN URLs, are preserved.

> [!CAUTION]
> Unix socket listeners are rejected — a WebView needs an HTTP(S) destination. To accept network clients, authenticate them through the `admission` hook instead of widening the listener.

## Development Workflow

```sh
bun --hot src/server.ts       # native window and authenticated browser, one backend
bunx --bun furin dev --web    # web mode, no SDK initialization
bun run build:desktop         # package the native app
```

- `furin dev` in a desktop project starts the native window **and** opens an authenticated owner session in the system browser. The single-use bootstrap URL expires after one minute and is passed directly to the OS browser — never printed or saved.
- `furin dev --desktop` skips only the browser owner session; `--web` runs web-only development, never loading the Electrobun SDK.
- `furin-electrobun dev` drives the same native development host.
- The preload activates only for the configured hot server entry, so ordinary imports and tests never initialize the SDK.

Frontend edits keep the window alive through Bun HMR and React Fast Refresh. Backend or native dependency edits trigger a controlled full process restart; native modules are never hot-reloaded, and backend state is not promised to survive. See [Desktop Architecture](/docs/desktop/architecture#packaging-and-development) for what the supervisor preserves.

## Packaging

```sh
bun run build:desktop
```

`furin-electrobun build` runs `furin build --target bun --output app` for you (passing each `desktop.external` package as `--external`), then prepares and builds the Electrobun project. Output goes to `.furin/electrobun/build`. The optional `--env=dev|stable` flag selects the SDK channel.

CEF and WebGPU bundling stay off by default; opt in per platform with `bundleCEF`/`bundleWGPU`, and note that a CEF renderer requires that platform's CEF assets. Native is the default renderer.

The npm Electrobun package is a launcher, not an API surface. Before checking native code, project the pinned devkit and extend its generated tsconfig:

```sh
bunx --bun furin-electrobun prepare
```

```json
{
  "extends": ["./.furin/electrobun/tsconfig.json", "../../tsconfig.base.json"]
}
```

Rerun preparation after relocating a checkout; published Furin declarations reference the original `electrobun/main` types only.

## Programmatic Use

`desktopApp()` accepts three forms: an options object, an inline factory that receives the decorators registered before it plus `store`, or the application and a factory. The factory runs synchronously at install time, before `.onStart()` — its services must already be usable:

```ts
new Elysia()
  .use(services)
  .use(desktopApp(({ access, torrents, instance }) => ({
    admission: access.admit.bind(access),
    background: () => torrents.settings.runInBackground === true,
    window: {
      frame: { height: 940, width: 1400 },
      renderer: "native",
      title: instance.name,
    },
  })));
```

`admission` and `background` remain callbacks and read shared services when invoked. The configuration context contains no HTTP request fields or per-request `.derive()` values.
