# Caching

Furin caches complete public route results according to the route's explicit rendering mode. Route caches are in-process and scoped to each mounted Furin instance; CDN caching is a separate layer controlled by response headers and an optional purge callback.

## Cache Contract By Mode

| Response | `Cache-Control` | `ETag` |
|---|---|---|
| SSR | `no-store, no-cache, must-revalidate` | None |
| SSG | `public, max-age=0, must-revalidate, s-maxage=31536000` | Build ID plus cache timestamp |
| Fresh ISR | `public, max-age=0, must-revalidate, s-maxage=N, stale-while-revalidate=N` | Build ID plus generation timestamp |
| Stale ISR | Same, with `s-maxage=0` | Existing ISR ETag |
| Cached route with `requestLoader()` | `private, no-store` | None |
| `/_client/*` assets | `public, max-age=31536000, immutable` | Not required; filenames are content-hashed |

Browsers revalidate cached HTML, while a shared cache may use `s-maxage`. When `If-None-Match` matches a current SSG or ISR entry, Furin returns `304` without the body.

SSG and ISR responses also expose `Cache-Tag` with the concrete resolved path. This is metadata for an upstream cache; it does not make an arbitrary CDN purge itself.

## ISR Lifecycle

For `mode: "isr"`, `revalidate` is seconds:

```tsx
export const route = defineRoute()
  .config({
    layout: rootRoute,
    mode: "isr",
    revalidate: 60,
    tags: ["posts"],
  })
  .loader(async () => ({ posts: await db.posts.findMany() }))
  .page(({ data }) => <PostList posts={data.posts} />);
```

1. A miss renders and caches only a healthy `200` result.
2. A fresh hit returns the stored HTML.
3. The first stale hit returns the old HTML and starts background regeneration.
4. Other stale hits reuse the same in-flight regeneration.
5. Success replaces the entry atomically; failure retains the last good entry.

ISR cache keys include the request search string. Avoid query-dependent SSG output: SSG entries are keyed by concrete pathname.

## Invalidate A Path

```ts
import { revalidatePath } from "@teyik0/furin";

revalidatePath("/blog/hello", "page");
revalidatePath("/blog", "layout");
```

`page` evicts the exact pathname. `layout` evicts the path and its descendants. The function returns whether an origin entry was deleted, queues an `X-Furin-Revalidate` signal for the current response, and invokes the configured CDN purger asynchronously.

Logical paths are unprefixed. `revalidatePath()` intentionally checks every mounted Furin instance; physical CDN purge paths include each instance prefix.

## Invalidate Tags

Declare data dependencies in route config:

```tsx
.config({
  layout: rootRoute,
  mode: "isr",
  revalidate: 300,
  tags: ["posts", "homepage"],
})
```

Then invalidate the concrete cached paths registered under those tags:

```ts
import { revalidateTag } from "@teyik0/furin";

revalidateTag("posts");
revalidateTag(["posts", "homepage"]);
```

Tag invalidation spans mounted instances but evicts only paths registered by each owning instance. Generated route types augment `FurinCacheTags`, providing autocomplete for tags discovered in route config.

Prefer tags when a mutation changes shared data used by several pages. Prefer paths when the changed URL is already known. This keeps invalidation precise instead of clearing the entire route cache.

## Browser Prefetch Invalidation

Furin mutation helpers add a response header such as:

```text
X-Furin-Revalidate: /blog/hello,/blog:layout
```

The generated router observes same-page browser `fetch()` responses, evicts matching prefetch entries, and refreshes the active route when it is affected. `applyRevalidateHeader()` is exported from `@teyik0/furin/link` for a custom integration, but application code normally does not need to call it.

For other tabs and devices, configure [Sync & Invalidations](/docs/sync). Sync distributes invalidation events; it does not turn the process-local HTML cache into a shared cache.

## CDN Purging

Register one process-wide callback at server startup when a CDN needs explicit invalidation:

```ts
import { setCachePurger } from "@teyik0/furin";

setCachePurger(async (paths) => {
  await cdn.purge(paths);
});
```

Furin batches and deduplicates physical paths for an invalidation call. The callback is fire-and-forget; a rejection is written to the structured logger and does not fail the mutation response.

An origin cache and a CDN cache must both be coherent. In a multi-replica deployment, each replica currently owns its own page cache. Purging only the CDN can allow another replica to repopulate it with stale HTML. Use a deployment strategy that coordinates origin invalidation or routes cached pages consistently until a shared page-cache adapter exists.

## Deploy Changes

Production responses include `X-Furin-Build-ID`; the initial document includes the matching meta value. If an SPA navigation reaches a different build, the client reloads the document instead of mixing old browser modules with new server output.

This build check protects code/data compatibility. It does not replace rolling-deployment coordination for origin caches or sync adapters.
